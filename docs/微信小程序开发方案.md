# 微信小程序开发方案

## 目标与现状

2026-10-27：前端统一为 Taro + React + TypeScript 微信小程序。原 `frontend/` Web 工程、Vite 页面构建、FastAPI 静态页面和开发 CORS 已移除。保留现有 FastAPI / LangGraph / SQLite 业务规则和单用户约束。

根目录启动脚本仅启动 API；安装脚本构建小程序，Docker 镜像只包含 Python API。微信开发者工具导入 `miniprogram/`，不再访问服务器根路径打开产品。

## 工程结构

`miniprogram/src/pages` 为页面，`components` 包含公共组件、修订与趋势；`api.ts` 适配 Taro 网络，`state.ts` 管理资源刷新、写入互斥、持久化原请求和隐私代际，`privacy.ts` 管理删除作业与导出副本。`types.ts` 独立保存 API 契约，不依赖已废弃的 Web 路径。

五个 Tab 为记录、历史、计划、发现、我的。今日、长期信息、权重提醒、通知与隐私管理为二级页面。长内容使用原生页面滚动和折叠区域；趋势采用小程序 View 条形图，并提供可读的逐日数值，缺失日期不当作零。

## 状态和恢复规则

1. 聊天、补充、计划、复盘、删除等有业务 request_id 的写入，在发送前持久化原地址、路径和参数。网络失败不会自动创建新编号。设备重启后仍可重试原请求；未核对前禁止并行写入和切换地址。
2. 服务端 `retry_request` 是补充和确认的恢复依据，不重建不同答案。`resuming` 时禁用确认；计划业务状态优先于流程收尾状态。只在页面前台轮询，离开后停止请求。
3. 所有页面资源有读取顺序与隐私代际校验，旧响应不能覆盖较新状态或恢复已删除内容。切服务或删除时清空跨页面私有内存。
4. 删除先预览、再弹窗明确确认。范围变化时保存新预览并停止旧请求重试；必须重新确认。删除作业编号持久化，未完成时提供查询和继续清理。
5. 应用内 JSON 导出副本记录路径，隐私删除前清理。已分享或另存到其他位置的文件仍由用户管理。API 密钥和 AppSecret 不进入客户端。
6. 聊天默认纯本地，服务器强制或恢复流程的纯本地限制不能升级。发送前展示供应商与数据类别；计划/复盘沿用服务端模型策略，强制全局不外发需设置服务端纯本地模式。

## 开发与部署

在 `miniprogram/` 运行 `npm ci`、`npm test`、`npm run typecheck`、`npm run build:weapp`。开发者工具导入此目录并配置 AppID，输出为 `dist/`。API 默认 `http://127.0.0.1:8000`，可在我的页修改，不带 `/api`。

真机的 127.0.0.1 不是电脑，需要可达的可信开发网络地址。正式部署需 HTTPS、微信后台合法域名、恢复域名校验。当前单用户服务没有登录鉴权，不能直接公网开放。个人版也需服务端身份校验；若开放多人使用，需 wx.login/code2Session、自有登录态，并将档案、记录、工作流/checkpoint、任务、血缘、导出、删除全链路隔离。

继续遵守同一数据目录只允许一个 Engine 的约束。不能直接通过增加 Uvicorn worker 扩容。站内消息不是微信订阅推送，订阅消息需要新增用户授权、模板和服务端发送能力。
