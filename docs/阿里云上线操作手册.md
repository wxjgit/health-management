# 阿里云上线操作手册

适用：现有 Ubuntu 24.04、2 核 2GB、40GB 云盘服务器。操作步骤与实际完成情况分开记录，当前服务器状态见 [阿里云部署进度](阿里云部署进度.md)。

## 一、先理解需要准备什么

服务器运行 Python 后端并保存 SQLite 数据；微信平台分发小程序；域名和 HTTPS 让小程序安全连接后端。

现有公网 IP 为 `120.26.121.163`。域名不是服务器自动附送的：如果你已有域名，可用它的子域名；没有时再注册一个。下面的 `api.你的域名` 都需要替换成真实值。

如果服务器位于中国内地，域名指向 API 服务也需要按阿里云要求办理 ICP 备案，不能因为只提供接口而跳过。还需在微信后台核对小程序主体、类目、小程序备案及隐私指引。

参考：[阿里云备案流程](https://help.aliyun.com/zh/icp-filing/basic-icp-service/user-guide/icp-filing-application-overview)、[添加域名解析](https://help.aliyun.com/zh/dns/pubz-add-parsing-record/)。

## 二、阿里云控制台操作

1. 打开服务器的远程连接，确认 Ubuntu 可以登录。不需要把服务器密码发到聊天里。
2. 在安全组或防火墙里，对外开放 HTTPS 的 443；80 用于证书验证与跳转。SSH 的 22 尽量只允许自己的 IP。不要公开后端的 8000 或数据库目录。
3. 在域名解析控制台添加记录：类型 A，主机记录 `api`，记录值 `120.26.121.163`。域名若不在阿里云注册，则在其实际 DNS 服务商操作。
4. 准备该域名的可信 HTTPS 证书和续期方式。私钥只留在服务器，不上传到代码仓库。

## 三、服务器目录与配置

安装 Docker Engine、Compose 插件、NGINX、Python 虚拟环境工具及 restic。Docker 安装按 [Ubuntu 官方安装说明](https://docs.docker.com/engine/install/ubuntu/)；备份工具按 [restic 文档](https://restic.readthedocs.io/en/stable/)。

将源码放到 `/opt/qingji`，不上传本机 `.env`、旧 data、node_modules 或虚拟环境。新数据目录为 `/srv/qingji/data`，先创建并赋予容器 UID/GID `10001:10001`，目录权限使用 `700`。

在服务器创建 `/etc/qingji/production.env`，权限 `600`。填写以下真实信息，不照抄占位值：

```dotenv
WECHAT_APP_ID=真实小程序AppID
WECHAT_APP_SECRET_SOURCE_FILE=/etc/qingji/wechat-secret
MODEL_API_KEY_SOURCE_FILE=/etc/qingji/model-key
MODEL_NAME=实际使用的模型名称
PRIVACY_OPERATOR=实际运营方名称
PRIVACY_CONTACT=实际联系邮箱
PUBLIC_API_ORIGIN=https://api.你的域名
HEALTH_DATA_SOURCE=/srv/qingji/data
PYTHON_PACKAGE_INDEX=https://mirrors.aliyun.com/pypi/simple/
DEBIAN_PACKAGE_MIRROR=http://mirrors.aliyun.com
BACKUP_RETENTION_DAYS=7
QINGJI_STACK_DIR=/opt/qingji
QINGJI_PYTHON=/opt/qingji/.venv/bin/python
QINGJI_BACKUP_STAGING=/var/lib/qingji/staging
RESTIC_REPOSITORY=已配置的异机备份仓库
RESTIC_PASSWORD_FILE=/etc/qingji/restic-password
```

三个密钥/密码文件各自只保存对应内容，放在源码之外。Compose 的只读 secret 挂载还需要让容器的 `10001` 用户能够读取微信和模型密钥；按实际宿主机权限设置所属组与只读权限，不要给所有人读取权限。restic 密码文件只供宿主机备份服务读取。

使用宿主机 Python 创建 `/opt/qingji/.venv` 并安装 `backend/requirements.lock.txt`，供备份及监控工具使用。生产 API 自身运行在容器里。

服务器访问 PyPI 较慢时，使用上述 `PYTHON_PACKAGE_INDEX` 让容器构建从[阿里云官方 PyPI 镜像](https://developer.aliyun.com/mirror/pypi)下载相同版本的依赖；未配置时仍使用 PyPI。宿主机安装依赖时也可在 pip 命令中加 `--index-url https://mirrors.aliyun.com/pypi/simple/`。保持 HTTPS 证书校验，不使用 `--trusted-host`。

`DEBIAN_PACKAGE_MIRROR` 用于出口代理构建时选择[阿里云 Debian 镜像](https://developer.aliyun.com/mirror/debian)，保留 Debian 的软件包签名校验；未设置时使用 Debian 原地址。它只修改构建容器内的软件源。

## 四、启动后端及 HTTPS

在 `/opt/qingji` 检查配置，再启动：

```sh
docker compose --env-file /etc/qingji/production.env -p qingji-hardened -f compose.hardened.yaml config --quiet
docker compose --env-file /etc/qingji/production.env -p qingji-hardened -f compose.hardened.yaml up -d --build
```

将 `deploy/public-nginx.conf.example` 中域名、证书路径改为真实值，检查 NGINX 配置后启用。该示例把公网 HTTPS 转发到本机 `127.0.0.1:8000`，不公开容器端口。

同时按 `deploy/network-policy.md` 在目标主机核对 Docker 子网冲突、防火墙与出口限制；配置文件存在不代表隔离已验收。登录来源 IP 的传递仅信任固定网关链，不能直接信任客户端发送的转发头。

验证访问 `https://api.你的域名/api/health` 正常；未登录访问 `/api/profile` 应返回 401。隐私说明里的运营方、邮箱、模型供应商必须与实际配置一致。

## 五、小程序正式构建与真机验证

微信后台配置相同 AppID 和该 HTTPS request 合法域名。小程序默认开启域名校验，正式包不再读取手机缓存中的开发地址。

在本地 `miniprogram` 目录，使用真实域名构建：

```sh
MINIPROGRAM_API_ORIGIN=https://api.你的域名 npm run build:weapp
```

Windows PowerShell 先设置 `$env:MINIPROGRAM_API_ORIGIN` 再构建。只有明确执行 `npm run build:weapp:dev` 时，才生成允许本机地址的开发包。

先上传体验版：两个微信账号分别验证登录、拒绝模型授权后的记录、同意与撤回授权、追问、导出、注销以及切换账号。不调用手机号码、头像等不需要的权限。平台隐私指引需与实际接口和自填健康信息处理对应。

## 六、备份、告警与恢复

先配置独立的加密 restic 仓库，不只把备份放在同一块服务器云盘；密码丢失会导致备份无法恢复，需另行妥善保存。按 restic 文档初始化并手动完成一次测试备份与恢复。

部署文件：

- `deploy/backup.sh`：暂停监督、短暂停服生成一致快照、恢复服务，再加密上传及执行保留策略。
- `deploy/systemd/qingji-backup.*`：每天上海时间 03:30 执行；实际停服时长需要在本机测试。
- `deploy/systemd/qingji-supervisor.service`：有上限的容器故障监督，不无限重启。
- `deploy/systemd/qingji-monitor.*`：每分钟检查接口、磁盘、队列、模型次数、容器内存和备份状态。

把 systemd 文件安装到服务器对应目录，核对其中的 `/opt/qingji` 路径，执行 daemon-reload 后按需启用。首次先手动启动一次服务检查日志，不要直接认为定时任务已工作。

告警地址写入 `/etc/qingji/alert-webhook`，权限 `600`。当前支持接收 `{ "text": "..." }` JSON 的 HTTPS webhook；其他通知平台需要相应接收适配。只有明确带 `--notify` 才发送，状态不变保持安静，故障变化或恢复时通知。未配置通知渠道前可不启用该 timer，先本地检查；这不算已完成生产告警验收。

备份快照包含哈希清单；恢复到全新空目录，禁止覆盖当前目录。在停服后使用最新的注销清单，不能仅使用旧备份内的清单：

```sh
PYTHONPATH=backend .venv/bin/python -m app.operations.backup restore \
  --snapshot /已从restic恢复出的快照目录 \
  --data-dir /srv/qingji/restored-data \
  --latest-deletions /保存的最新account-deletions.jsonl
```

恢复会清除所有旧登录凭证，并剔除已注销账号。最新注销清单需要持续妥善保存到独立可靠位置；如果灾难后无法取得最新清单，不应直接用旧快照恢复对外服务。恢复完成后核对目录属主 `10001:10001` 和权限，再修改数据挂载路径并启动。失败恢复留下标记时，服务会拒绝启动。

## 七、发布与回滚

发布前记录代码版本和镜像 ID，保存已验证镜像标签，不只依赖 `latest`。升级前先完成备份；若升级改变数据库结构，回滚必须同时评估数据库版本兼容，不能只换旧程序。演练时使用合成测试数据卷。

`scripts/test-runtime-deployment.py` 只对专用 `qingji-runtime-test` 项目运行，使用合成账号，不能拿真实用户数据做故障注入。`scripts/verify-runtime.py` 仍会把未实测的网络、恢复与压力项目列为未验收。

在此服务器上完成并发聊天、用户引擎冷启动、后台报告、磁盘满和重启恢复测试。确认响应时间、错误率、内存及任务排队后，才决定是否需要升级 2GB 内存。先开放 10–30 人试用，再逐步扩大；当前没有 1000 用户生产容量结论。

本轮本机短基准仅运行合成记录：每种模式 40 个样本，开启运行日志后的 p95 约 18.7ms，相对开销约 8.5%，未达到脚本原定的 5% 参考目标。没有包含真实模型网络调用或目标服务器负载，不能用它作为生产性能通过的依据。
