# 咨询链路改造

模型负责识别意图、选择类型化数据视图、给出明确日期与记录指代。服务端仍负责输入结构、数据最小化、记录绑定、写入证据和资源上限。本次不包含账号与多用户隔离改造。

## 模型模式

- 咨询和查询不再由疑问词、领域词表二次授权；使用枚举数据视图和查询类型。
- `view_start/view_end` 是 ISO 日期，必须成对。单日饮食限1天，饮食回顾限7天，体重趋势限28天。未提供日期时使用当前日期结束的默认工具窗口，不重新猜测自然语言日期。规划提示要求表达日期的用户请求显式返回窗口。
- 单餐工具必须绑定唯一餐食，否则澄清。历史结果只在当前对话内解析。旧检查点仍可使用已有指代提示作兼容，不能据此绑定任意记录。
- 查询仍限制最多100条，查询起止跨度最多365天。写入仍需原文证据，模型不能借咨询输出修改记录。
- 计划被本地校验拒绝后最多重新规划一次，使用原输入和相同的数据权限，不自动重试网络或鉴权错误。结构无法解析的模型响应目前仍走明确的模型格式错误。
- 普通咨询可返回自然语言 `answer`，必须由第二次独立模型调用审核。审核必须通过并逐字返回同一草稿才能展示。不能将模型自称 `approved` 当作审核完成凭据；内部审核标记不进入公开JSON。
- 审核或生成失败时使用本地建议；实际保存回执、取消记录、缺失字段追问继续由本地渲染。
- 感受反馈不再抢先覆盖模型已识别的咨询。离线演示模式保留原有规则解析，不会擅自联网。

## 风险与观测

独立模型审核是概率性检查，不是事实正确或医疗安全的保证；模型可能错误选择仍在工具边界内的视图。禁止访问其他用户、任意数据库字段和模型自定SQL的权限控制不能交给模型。当前项目仍是单用户版本。

记录 `model_plan_*` 校验原因、`model_tool_window_invalid` 和 `model_plan_repair`，不记录模型回复和健康原文到错误日志。自然回答增加一次模型调用及相应延迟和费用；所有调用仍受单次工作流执行预算约束。
