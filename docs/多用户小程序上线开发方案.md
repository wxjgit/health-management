# 轻记：多用户小程序上线开发方案

更新日期：2026-10-29

## 1. 目标与当前进度

面向约 1000 个注册用户的微信小程序，初期继续使用 SQLite，计划部署到现有阿里云服务器。

| 步骤 | 当前情况 |
| --- | --- |
| 第一步：微信登录 | 已实现登录、内部账号、凭证过期与退出撤销；真实微信登录待配置密钥后联调 |
| 第二步：用户数据隔离 | 已实现按账号独立数据库、业务接口开放、后台任务归属，仅保留登录后的多用户模式 |
| 第三步：并发与费用控制 | 已实现请求限流、模型总并发、每日调用额度和输出长度限制 |
| 上线功能补充 | 已实现版本化隐私与健康信息同意、可撤回模型授权、账号注销与整账号清理、数据导出 |
| 第四步：生产部署 | 已提供 HTTPS、备份恢复、监控定时任务及部署手册；目标服务器配置与演练待完成 |
| 第五步：分批开放 | 待真实微信联调和目标服务器压测后逐步试用 |

1000 个注册用户不等于 1000 人同时使用。当前测试验证功能与隔离，不代表已经确认服务器容量。

## 2. 部署与数据在哪里

服务器候选：Ubuntu 24.04，2 核 CPU、2GB 内存、40GB 云盘。模型通过外部 API 调用，不在这台机器上运行。部署前检查带宽、磁盘余量和已有服务占用。

访问流程：微信小程序 → HTTPS 后端 → 服务器上的 SQLite 文件。

多用户模式的数据目录：

```text
DATA_DIR/
  accounts.db                账号与登录凭证摘要
  usage.db                   请求次数与模型调用额度
  account-deletions.jsonl     最小注销清单，恢复时排除已注销账号
  observability/             服务运行日志
  users/
    内部账号ID/
      health.db              此人的档案、记录、聊天、计划、报告、提醒等
      checkpoints.db         此人的待追问与工作流进度
```

服务器建议使用 `/srv/qingji/data`；加固容器内部仍使用 `/data` 并挂载持久化存储。以上是计划路径，不代表已经部署。

## 3. 第二步的隔离方式

采用“每个账号独立一组 SQLite 数据库”，替代原计划中给所有表增加用户字段的做法。这样现有工作流恢复、来源追踪和隐私删除可以完整保留，各账号的数据库连接、缓存和锁也相互独立。

- 后端只根据验证后的登录凭证选择账号目录，前端不能指定其他用户或文件路径。
- 档案、健康记录、长期信息、聊天、计划、报告、提醒、导出和删除全部使用当前账号的数据库。
- 同样的请求编号、会话编号和去重编号可以在不同账号独立使用，不会复用别人的结果。
- 拿到其他账号的记录、工作流或删除预览 ID，也不能读取、确认或删除对方的数据。
- 等待模型时释放当前用户的工作流锁，数据库事务不能跨越模型等待。
- 模型并发、每日总额度和运行资源限制全局共享，不会因为增加账号而扩大总上限。
- 内存默认只缓存 8 个用户引擎。空闲引擎可淘汰，磁盘数据保留；使用中的引擎不会关闭。全部繁忙时返回服务繁忙提示。
- 小程序切换账号时清理本机私有状态；待处理请求和删除预览绑定账号，旧账号的延迟响应不进入新账号页面。

每个用户库只保存本人的数据，因此沿用库内日期、事件类型和任务到期索引，不再需要跨用户复合索引。将来若需要跨用户统计或多实例部署，需要另行设计。

## 4. 登录与运行配置

服务只支持微信登录，必须填写以下配置；缺少 AppID 或 AppSecret 时启动失败：

```dotenv
WECHAT_APP_ID=你的小程序AppID
WECHAT_APP_SECRET_FILE=/仓库外的绝对路径/wechat-secret.txt
AUTH_SESSION_SECONDS=604800
TENANT_CACHE_SIZE=8
PRIVACY_OPERATOR=真实运营方名称
PRIVACY_CONTACT=真实联系邮箱
PUBLIC_API_ORIGIN=https://真实API域名
```

密钥文件只写 AppSecret，不放入版本库。小程序填写相同 AppID，后端读取密钥，客户端不会收到 AppSecret 或微信 session_key。修改配置后重启服务。

| 接口 | 作用 |
| --- | --- |
| `POST /api/auth/wechat/login` | 接收微信 code、当前协议版本、隐私及健康信息同意和可选模型同意 |
| `GET /api/policies` | 公开查看隐私政策、模型说明和版本 |
| `GET/PUT /api/auth/consent` | 查询或更新本人授权，模型默认关闭，可撤回 |
| `DELETE /api/auth/account` | 确认注销，撤销全部登录并清理账号数据 |
| `GET /api/auth/me` | 查询本人内部账号 ID |
| `POST /api/auth/logout` | 撤销当前登录凭证 |
| `GET /api/auth/usage` | 查询本人当天模型调用次数和剩余额度 |

除登录和公开状态接口外，使用 `Authorization: Bearer <access_token>`。登录默认 7 天有效，退出仅撤销当前凭证。健康业务接口现已在多用户模式开放。

加固容器已配置微信密钥挂载和 `api.weixin.qq.com:443` 出口白名单；部署时必须提供 `WECHAT_APP_ID`、仓库外的 `WECHAT_APP_SECRET_SOURCE_FILE`，以及原有模型配置。真实微信登录仍需用自己的 AppID、AppSecret 和微信开发者工具/真机联调。

## 5. 并发与费用配置

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `USER_REQUESTS_PER_MINUTE` | 60 | 每账号每分钟 API 请求数 |
| `GLOBAL_REQUESTS_PER_MINUTE` | 600 | 全服务每分钟 API 请求数 |
| `MODEL_MAX_CONCURRENT` | 2 | 全服务同时进行的模型调用数 |
| `USER_MODEL_CALLS_PER_DAY` | 200 | 每账号每天模型调用尝试数 |
| `GLOBAL_MODEL_CALLS_PER_DAY` | 5000 | 全服务每天模型调用尝试数 |
| `MODEL_MAX_OUTPUT_TOKENS` | 4096 | 单次模型最大输出长度 |

这些是保护值，不能直接当作服务器容量指标。原有工作流、读取和管理操作的并发限制继续生效。

请求按固定自然分钟计数；模型额度按上海日期重置。模型请求发出前预占额度，失败、超时和取消不退还；没有拿到并发名额时不扣调用额度。已完成请求重放不重复调用；未完成请求如果需要重新调用供应商，会计入新的尝试。

`usage.db` 保留最近少量分钟窗口和当前及此前七天的模型次数，不保存健康原文。存储不可用时停止调用，不跳过保护。

这里控制调用次数和输出长度，不是精确人民币账单；一次聊天可能调用模型多次。供应商侧仍需设置预算与费用提醒。

## 6. 后台任务与运维

多用户模式使用一个共享后台线程，轮流访问已建立数据目录的账号。每次最多扫描 10 个账号，每账号每轮最多领取一个任务；规划时间与任务状态保存在各自用户库，缓存淘汰和重启后仍能恢复。单个慢任务可能延迟后续账号，需在服务器试用中观察排队时间。

日报、周报、提醒、归档和 outbox 都在所属用户引擎中处理，模型调用也计入该账号额度。只有注册表中的真实账号会被后台扫描。关闭调度或任务执行的配置继续生效。

仍只允许一个应用进程持有整个数据根目录，不增加 Uvicorn worker。内部监控接口在多用户模式暂不开放，避免把全服务信息提供给普通账号；生产监控入口另在部署阶段配置。

离线管理某账号任务时，先停服，再在 `backend` 目录运行：

```sh
python -m app.jobs.manage --data-dir /实际数据目录 --user-id 内部账号ID status
```

后续可把 `status` 换为 `pause`、`resume`，或按原任务管理方式重试指定失败任务。命令同时检查根目录与用户目录的独占锁，避免和在线服务竞争。

## 7. 数据从空账号开始

不保留单用户模式、免登录入口或旧数据迁移命令。此次开发已停止本机旧服务，清空工程 `data` 目录里的旧数据库、WAL/SHM 文件和运行日志，不做迁移或备份。

新用户第一次访问自己的业务接口时创建独立数据库；未登录请求不会创建用户目录。运行数据目录已加入 Git 忽略规则，后续账号、健康数据和工作流状态不进入源码版本管理。

## 8. 上线前剩余工作

本轮已提供应用内授权、注销、数据导出、正式域名构建保护、备份恢复与告警工具。配置及真实服务器步骤见 [阿里云上线操作手册](阿里云上线操作手册.md)。下面是实际环境中仍需完成的配置和验收，不能把模板等同于已部署。

- 完成真实微信登录和真机联调，核对主体、服务类目及平台要求。
- 配置域名、HTTPS、正式密钥、权限和故障重启。
- 备份范围包含账号库、额度库和所有用户目录；初期可安排短暂停服一致性备份，并演练完整恢复。
- 配置内存、磁盘、接口延迟、后台排队和模型费用监控，以及发布回滚。
- 先内部双账号验证，再约 10–30 人、约 100 人试用，最后逐步面向 1000 个注册用户。
- 压测同时覆盖登录、聊天、追问、查询和后台报告，记录错误率、数据库等待、响应时间和资源占用，再决定是否升级内存或数据库。

自动化检查覆盖未登录访问、双账号数据隔离、跨账号 ID 越权、工作流与计划确认、删除、导出、通知、后台任务、模型额度、缓存淘汰、重启恢复、缺少登录配置时拒绝启动和客户端账号切换。测试使用模拟微信与模型响应，不代表已经完成生产部署或真实流量验收。

登录限流已改为可配置的全局每分钟 300 次、每来源每分钟 20 次；代理来源链和阈值仍需目标环境实测。备份恢复必须提供最新的注销清单，清除旧登录凭证并排除已注销账号。告警仅在显式配置并启用通知后发送，状态不变保持安静。
