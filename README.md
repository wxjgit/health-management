# 轻记 · 个人减脂 Agent

一个单用户、可本地运行的网页原型。用自然语言记录饮食、体重、睡眠、运动和生理周期，数据保存在 SQLite 中；LangGraph 负责解析、关键追问、纠错、历史检索、计划确认和复盘流程。

## 现在可以使用的功能

- 个人建档、五类自然语言记录、跨天补记、关键缺失追问。
- 自然语言纠错、按日期/类型/关键词查询、当日营养汇总和历史趋势。
- 用户设定热量与三大营养素目标；生成下一餐建议、次日重点和一周安排。
- 小幅目标变化自动生效；初次、单次或累计超过 5% 的变化需要确认；过时草案不会生效。
- 有证据的睡眠/摄入、工作日/周末规律；展示样本、窗口、覆盖率和限制，支持认可/否认。
- 根据完整饮食记录给出可确认的权重建议；手动调整权重和提醒时间。
- 日报、周报、后台站内提醒、数据导出、删除、超过一年后的月度归档。
- 服务重启后恢复记录与待追问事项；请求重试去重。

## 启动

环境要求：Python 3.11+、Node.js 22.12+。本机已使用 Python 3.14.5 完成测试。

项目已安装依赖并构建前端。在项目根目录运行：

```powershell
.\start.ps1
```

然后打开 <http://127.0.0.1:8000>。服务同时提供 API 与前端，不需要分别启动两个服务。终端保持运行；按 Ctrl+C 停止。端口被占用时使用 `.\start.ps1 -Port 8002`。

如果 PowerShell 不允许运行脚本，可以直接使用等价命令：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

在新电脑首次安装依赖，运行 `.\setup.ps1`；脚本需要访问 Python 与 npm 下载源。Python 依赖锁定在 `backend/requirements.lock.txt`，前端锁定在 `frontend/package-lock.json`。

## 模型配置与演示模式

正常启动时，后端直接使用 `backend/app/config.py` 中固定的百炼兼容接口、API Key 和 `qwen3.8-max` 模型。用户在网页中提交自然语言后，内容会发送给该外部模型服务。

代码测试可以显式构造无模型配置的 `Settings` 进入演示模式。演示解析覆盖常见中文表达，页面明确提示其营养数值来自固定示例，不是完整或已核验的营养数据库。无法识别的食物保存为营养未知，不算成零。

演示模式可以验证这些表达：

```text
中午吃了一大碗牛肉面，加了一个卤蛋
不是大碗，是小碗
今天早上体重65公斤，昨晚睡了7小时
今天跑步30分钟，有点累
今天月经开始了
查看最近7天的饮食记录
我不喜欢燕麦
```

后端调用兼容 Chat Completions 的 `/chat/completions` 接口，用 Pydantic 验证结构化输出。模型解析会收到本次输入及检索到的相关记录；密钥不会传到浏览器或数据导出。模型失败会明确报错，不悄悄切换到演示估算。

当前模型接入主要负责输入理解；统计、营养求和、权重建议、计划差异校验与初版建议模板由代码执行。自动化测试使用模拟响应，不会产生模型费用。

## 使用顺序

1. 建立基础档案，在对话页记录一餐和身体状态。
2. 分量缺失时回答追问；如果暂时不知道，直接说“不知道”。也可以取消或另开一条记录。
3. 在历史页查询和纠正记录；日期默认按上海时区解析，睡眠记录按入睡日期归属。
4. 在计划页填写你希望采用的热量和营养目标，确认草案后生效。首版暂不自动推算个体减重热量，目标期望周期不会直接转成节食强度。
5. 当天饮食全部记录完成后，点击“确认今日饮食已记录完整”。只有完整且营养信息齐全的日期用于摄入规律分析。
6. 持续积累数据，生成周复盘；数据不足时不会强行生成规律。

用户提供包装营养信息时，可用“午餐喝了一杯牛奶，热量120kcal，蛋白质8克，碳水12克，脂肪4克”。这代表实际食用份量的总营养，不是每 100g 数值；多食物或复杂标签建议接入真实模型并检查记录。

## 数据与提醒

`data/health.db` 保存健康事实；`data/checkpoints.db` 保存 LangGraph 工作流进度。此目录和 `.env` 均被 Git 忽略。每条记录有发生时间、创建时间、修订版本和营养来源。

删除健康记录时，为清理相关数据副本，会清空聊天上下文、派生复盘/规律和待处理事项；其他健康事件保留。生效的数值目标保留，相关具体安排清空。删除前网页会明确提示这一范围。归档先生成并校验完整过期月份的摘要，再清理原文及相关上下文；边界月份待整月过期后处理。

删除完成会清理 SQLite 页和 WAL。应用不自动创建备份；用户自行导出的文件或复制到其他位置的数据库不在应用清理范围内。超过一年后的摘要无法恢复逐餐细节，也不能用来精确复核逐日相关性。

后台每分钟检查站内任务。网页关闭时服务仍可生成消息，下次打开后查看；当前没有设备级推送。服务停止期间不会实时提醒，重启时补生成最近七个有记录日期的日报。站内提醒允许关闭，记录允许跳过。

## 开发与验证

后端开发：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000 --reload
```

前端开发，在 `frontend` 目录运行 `npm run dev`，打开终端显示的本地地址。Vite 会把 `/api` 转发给 8000 端口。

后端测试，在 `backend` 目录运行：

```powershell
..\.venv\Scripts\python.exe -m pytest -q
```

前端在 `frontend` 目录运行 `npm test` 和 `npm run build`。测试分别覆盖数据与 LangGraph 生命周期、前端空状态、请求重试、独立记录及计划确认。前端 DOM 测试不等于真实浏览器视觉检查。

结构：

```text
backend/app/
  main.py         FastAPI 接口与启动生命周期
  graphs.py       交互、计划确认、规律与复盘三个 LangGraph 图
  parser.py       演示解析与真实模型适配
  repository.py   SQLite 数据、修订、任务和去重
  nutrition.py    营养求和与明确标注的演示值
  services.py     历史、分析、计划、权重建议、归档
  scheduler.py    后台任务与站内消息
frontend/src/
  App.tsx         五个页面与交互
  types.ts        API 数据类型
  styles.css      响应式界面
```

完整设计见 [开发文档](docs/开发文档.md)。原型使用 Python 自带 SQLite Repository 和版本化初始化，暂未引入 SQLAlchemy/Alembic；页面部署采用同一 FastAPI 进程。只监听本机，不包含公网访问保护或多用户隔离。

初版仍需要继续完善：经核验的营养数据来源、更细的偏好/限制匹配、基于实际执行效果的个性化计划生成、更多统计模板和设备级通知。当前数值目标由用户提供，规律与权重学习是明确的规则模板，不能承诺医学适配或减重效果。
