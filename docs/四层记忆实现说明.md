# 四层记忆实现说明

本次实现沿用 SQLite、LangGraph 和现有 provenance。业务库迁移到版本 6，所有新增表使用幂等初始化；迁移不删除业务事实，不把历史文本自动解释为新类型。

## 1. 工作记忆

`workflow_activity` 保存最后活动时间和截止时间；原始输入、草稿、待补字段及追问轮次继续使用 checkpoint。有效操作更新活动时间，普通查询不会延长期限。

| 配置 | 默认 | 对象 |
| --- | --- | --- |
| `CONTEXT_PENDING_DAYS` | 7 天 | 待补草稿和未完成聊天 |
| `CONTEXT_PLAN_DAYS` | 7 天 | 待确认计划 |
| `CONTEXT_COMPLETED_DAYS` | 30 天 | 已完成/失败/取消的流程上下文 |

清理顺序：持久化过期作业与最小请求凭据，标记流程过期并提高 generation，清理 checkpoint、聊天和回执副本，压缩数据库，再完成作业。活动中的流程持有执行锁，维护不会强行删除；写入与恢复仍检查截止时间。清理失败保留 `context_expirations.state=pending`，下次维护或启动时重试。

`expired_requests` 仅保留请求 ID、线程 ID 和时间，用于阻止旧请求重新执行。`context_expirations` 仅保存已保存事件的 ID、清理状态和时间；删除事件时同时移除对应 ID。事件事实与独立证据不会随草稿过期删除。

旧数据库没有活动时间的工作流使用原创建时间作为过期判断的回退。过期事项不允许继续补充，界面提供重新开始，并说明此前保留的记录。

## 2. 事件账本

`events` 是当前快照，`revisions` 追加每一版事实；`revision_context` 保存对应操作标识，通过外键随修订删除。修订查询返回原文、原因、时间、来源操作和业务字段差异。旧修订没有来源操作时明确返回空值。

纠错在仓储事务内校验 `expected_version`，更新 SQL 同时匹配旧版本；旧请求重放先走操作去重。食物与分量变化继续使用现有营养证据校验和估算失效机制。

隐私删除清理全部修订、来源操作和副本；归档后只能查看月度摘要，逐条修订接口返回不存在/已归档。

## 3. 结构化长期事实

兼容保留 `facts` 基表，`fact_details` 保存结构化状态，`fact_revisions` 追加变更快照。两张扩展表通过外键随事实删除。历史自由文本读取为 `legacy_text/source_kind=legacy`，不伪造原文来源与适用期；首次修改或撤回时先保留旧版快照。

主要字段：`type`、`subject`、`value`、`source_kind`、`confirmation`、`lifecycle`、`valid_from`、`valid_until`、`supersedes`、`evidence_message_id`、`version` 和 `schema_version`。

确认状态与生命周期分开：

- 确认状态：`candidate`、`confirmed`、`conflict`。
- 生命周期：`scheduled`、`active`、`needs_review`、`superseded`、`retracted`、`expired`。

`confirmed` 表示用户明确陈述，不代表事实经独立核验；专业建议来源记录为用户转述。

本地规范化仅处理可完整匹配的明确偏好表达，如“不喜欢燕麦”“现在可以接受燕麦”“这周不吃燕麦”。不使用语义相似度猜测食物别名；无法确定的明确文本保留原文，假设和疑问不能成为有效已确认事实。模型仍须经过原安全入口，不新增自动记录诊断或用药推断能力。

永久普通偏好的明确更新可以替代旧偏好。临时例外产生冲突，要求用户选择；未选择时不用于普通建议。临时冲突到期后，剩余的原偏好可恢复。未来日期的事实保留为待生效，到达日期再处理替代或冲突。过敏、专业建议和其他限制不通过普通偏好更新解除；到期进入待核对状态，继续保留保护。用户可编辑有效期或明确撤回。

事实更新使用版本检查；聊天保存与重复语句通过最小操作凭据去重，重试旧语句不会覆盖新偏好。撤回保留历史；隐私删除继续使用原预览和可恢复清理流程，覆盖所有事实快照及来源副本。

## 4. 派生结果

`health/derived.py` 维护算法版本及公共 `memory` 元数据：方法、参数、生成时间、窗口、状态、失效原因、是否可重算。既有来源 ID、来源版本和查询范围仍由 provenance 管理；展示证据不替代真实依赖。

| 对象 | 数据变化 | 时间/方法变化 |
| --- | --- | --- |
| 当前规律 | 相关来源变化后失效 | 滚动窗口或算法变化后需重算 |
| 历史复盘 | 标记原结果需更新 | 保留原窗口；不因进入下一周而自动过期 |
| 待确认计划 | 依赖变化后不能激活 | 算法或安排日期失效后不能沿用旧草案 |
| 生效计划 | 保留目标与决策，标记需复核 | 不自动修改目标；现有安全限制仍阻止相关生成/执行 |
| 月度摘要 | 显式删除来源贡献时删除受影响摘要 | 保留聚合版本与精度；明细已删除时不能重算 |

旧结果没有方法版本时展示 `unversioned/legacy_version_unknown`，不追认其为当前算法。重算通过现有复盘、计划与作业入口执行，不在普通读取时调用模型。

## API

| 接口 | 用途 |
| --- | --- |
| `GET /api/facts?include_inactive=true` | 管理全部长期信息，默认仅取有效已确认信息 |
| `POST /api/facts` | 用户明确新建事实 |
| `PUT /api/facts/{id}` | 携带 `expected_version` 修改事实 |
| `PATCH /api/facts/{id}` | `confirm` 或 `retract`，携带版本 |
| `GET /api/facts/{id}/revisions` | 事实变更记录 |
| `GET /api/events/{id}/revisions` | 事件修订与差异 |
| `GET /api/workflows/expired` | 最近过期事项和已保留事件数量 |
| `GET /api/insights?include_stale=true` | 包含需更新规律的管理展示 |

事实与事件删除沿用原有 `/api/deletions/preview` 和 `/api/deletions`，不绕过影响范围确认。

## 验证

`backend/tests/test_memory_layers.py` 覆盖事实替代、临时冲突、未来生效、来源类型、撤回、版本冲突、历史迁移、派生结果失效、摘要版本、过期恢复、旧请求重放和修订一致性。`frontend/src/MemoryPanels.test.tsx` 覆盖编辑版本与期限、失败保留、撤回/删除分离、冲突选择、异步修订响应、过期提示及方法版本展示。

回归继续覆盖原模型发送边界、安全路由、营养准备、计划确认、并发和精准删除。测试使用临时数据库与模型桩，不读取实际健康库，不产生模型调用费用。
