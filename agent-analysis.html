什么会成为长期记忆

“写进数据库”不等于“成为用户长期事实”
facts · 跨对话语义事实 仅用户明确说出的喜欢 / 不喜欢、过敏、忌口、长期饮食限制、医生明确要求；source=user、status=confirmed。
events · 可追溯健康历史 完整并校验通过的饮食、体重、睡眠、运动、周期；修正写 revisions。偏咸 / 油腻 / 吃撑 / 仍饿只随对应餐食保存。
不进入 facts 模型推断、营养估算、助手建议、单次体验、假设问题、未完成或取消草稿。普通消息即使暂存，也不是健康事实。

存储清单与清理规则

当前实现 · 无 embedding / vectorstore / 自动相似度召回
存储写入条件主要读取方保留 / 失效
facts解析为 fact 且 fact_text 存在；由 fact 节点确认写入respond、recommendation、targets、plan无自动过期；用户可单条删除
events + revisions必需字段齐全、结构校验通过；persist / save_ready 写入parse 纠错、dashboard、advice、plan、analysis原始记录约 1 年；之后保留月度摘要
meta用户通过 API 保存 profile / preferences；系统写完整日和版本目标估算、建议、计划、提醒调度覆盖更新；当前没有自动过期
messages聊天请求、补充回答和助手结果聊天界面；仅处理“这 / 那 / 刚才”时取最近用户消息30 天清理；助手消息从模型事实上下文排除
workflows / receipts / checkpoints每次 run / interrupt / resume 与幂等回执Engine 恢复流程、验证 request_id、防重复写入完成流程 30 天；等待输入最长 366 天
plans / insights / reviews计划、规律分析和日报 / 周报生成后计划页、趋势页、建议中的 active targets数据版本变化使 insight 失效；非事实型派生数据
monthly_summaries调度器校验月度汇总成功后，才删除对应旧事件超过一年后的历史概览无自动过期；只保留月级统计

真正传给模型的记忆

先由本地代码筛选，再发送结构化子集
parse本地取近期记录，模型最多看到 recent_records[:12]；用于意图与纠错定位。
respond · advice按问题选今天 / 7 天 / 28 天窗口；最多 8 条限制、5 条偏好。
指代解析只有问题包含“这 / 那 / 刚才”时，附同会话最近 2 条用户消息；不附助手回复。
plan / analysis计划读取近期 30 条事件与 facts；分析读取 28 天结构化记录和完整度。

生命周期

定时 scheduler 每分钟检查，归档和上下文清理具备幂等 job 记录
30 天清理旧 messages；已完成 / 失败 / 取消工作流及其 checkpoint、receipt 一并移除。
366 天仍在 waiting_input 的流程到期后清理，避免悬挂草稿无限保留。
超过 1 年只归档完整过期月份；摘要校验成功后删除逐条 events 和 complete:day。
无自动过期profile、preferences、facts、active plan、monthly_summaries 继续保留，直到更新或删除。
删除防残留 删除 event 或 fact、以及完成归档时，会清空可能含副本的对话 / workflow / receipt / 派生上下文，并 purge 全部 checkpoints。

五类调用逐项说明

“阻断”表示失败会返回 409；“可降级”表示主流程仍可完成
parse 节点 · 首轮输入model_parse()
失败阻断
触发model 模式下的新聊天；记录、纠错、查询、咨询、长期事实都先经过它。
输入now / text / original / selected_id / recent_records[:12] / schema
输出ExtractionResult：intent、事件草稿、feedback、追问字段、查询范围、fact_text。
复核纠错 ID 必须来自已检索记录；反馈只接受本轮原话，随后进入 validate_drafts。
失败请求、JSON 或 Schema 任一失败 → ValueError → workflow failed → HTTP 409；不切 demo。
parse 节点 · resume 补充patch()
失败阻断
触发clarify 恢复后需要真正补字段时；取消、不知道或转为咨询由本地逻辑处理，不调用。
输入本次回答 / checkpoint 草稿 / requested_fields / item_index / now / schema
输出EventPatch：只允许待补字段及本轮 feedback，不返回完整事件。
复核merge_patch 只合并白名单字段；不能改已知日期和食物，也不能用历史记录补空缺。
失败模型或结构化输出失败 → HTTP 409；已有草稿仍由 checkpoint 管理。
prepare_nutrition 节点estimate_nutrition()
可降级
触发准备保存的 meal 有明确食物和实际分量，但热量或三大营养素仍缺失。
输入name / quantity / unit / size / cooking / requested_nutrients / provided_nutrients
输出NutritionEstimates：按 item index 返回缺失数值与 uncertainty。
复核索引唯一、用户值优先、描述指纹匹配；热量与宏量能量差超过 max(50 kcal, 35%) 就拒绝。
失败食物和分量照常保存；缺失营养保持 unknown / partial，并写明失败原因，不按 0 处理。
prepare_clarification / respond 节点phrase_reply()
可降级
触发本轮存在 salty / oily / overeating / hungry 反馈，且本地 make_plan 产生批准要点。
输入plan.points / feedback 标签 / stage / context.foods[:3] / boundary / schema；不读取历史聊天。
输出ContextualReply：每个 segment 必须保留 point_id，只负责自然表达。
复核点位与顺序完全一致；检查主题锚点、长度、数字、日期、保存状态、诊疗和新增建议。
失败使用本地 ACK / GUIDANCE 原文；医学或钠边界由程序追加，记录写入结果不受影响。
respond 节点 · 普通咨询answer_advice()
可降级
触发intent=advice，且不是医疗边界、保存回执、查询或 feedback-only 路径。
输入场景化只读 context：问题、目标、facts、今天 / 7 天 / 28 天窗口；指代时最多 2 条用户消息。
输出AdviceReply.answer：直接回答重点，最多两条可执行建议。
复核禁止上下文外数字、诊疗结论、把不完整记录说成全天结论、把剩余额度说成必须吃满。
失败按同一个 context 生成 fallback_advice；不会将失败回答写成事实或事件。
